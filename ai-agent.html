THREE AGENTS

三个智能体，覆盖规划、问答与自主执行

应用层复用 ChatClient、会话记忆、Advisor、工具注册与流式接口，再根据业务场景组合不同能力。

TRAVEL PLANNING AGENT

TripMind：生成可直接采用的个性化旅行计划

根据目的地、日期、兴趣和预算组织结构化 Prompt，结合高德地图与 MCP 工具查询地点和路线，输出按天编排的行程、交通建议、天气准备和费用明细。

  • 地图工具补足模型缺少的实时地点与路线信息
  • 预算约束贯穿每日行程，并支持生成 HTML 与 PDF
  • 通过 SSE 分段输出，降低长攻略的首屏等待时间
RAG CONVERSATIONAL AGENT

EmotionalMaster：结合知识库的多轮情感问答

通过领域 Prompt、ChatMemory 与安全边界组织连续对话；使用 RAG 完成 Markdown 文档摄取、查询重写、向量检索和 Advisor 上下文增强，让回答能够参考相关领域资料。

  • MessageWindowChatMemory 按 chatId 隔离多轮会话
  • QuestionAnswerAdvisor 将检索片段加入模型上下文
  • 支持元信息过滤、相似度阈值、TopK 与 PGvector 切换方案
GENERAL-PURPOSE AGENT

ReAct Agent：在受控循环中自主执行任务

采用 BaseAgent → ReActAgent → ToolCallAgent 分层设计。模型生成 ToolCall，后端执行工具并把 ToolResponse 写回历史，循环完成“思考—行动—观察”，直到任务结束。

  • 统一接入文件、网页、资源下载、终端和 PDF 等工具
  • 手动维护工具调用历史，完整记录每一步参数与结果
  • 通过状态机、最大步数和终止工具限制执行边界
REACT AGENT · EXECUTION LOOP

一次复杂任务如何从自然语言走到工具执行？

ReAct Agent 通过“思考—行动—观察”的受控循环逐步完成复杂任务。

1

接收任务

校验输入和当前状态，将用户消息写入智能体上下文。

2

模型思考

结合系统 Prompt、历史消息和工具清单判断下一步。

3

执行工具

ToolCallingManager 调用模型选中的 Java 或 MCP 工具。

4

写回观察

将 ToolCall 与 ToolResponse 追加到会话历史。

5

继续或终止

生成最终答案、调用终止工具或达到步数上限时结束。

IDLE→RUNNING→FINISHED异常分支 → ERROR
ENGINEERING HIGHLIGHTS

把模型能力组织成可扩展应用

三个智能体共享基础组件，同时保留各自的业务流程与执行边界。

⌕

查询重写 + 多策略 RAG

EmotionalMaster 先用 QueryRewriter 优化检索表达，再通过 QuestionAnswerAdvisor 接入向量库；同时支持元信息过滤、相似度阈值和 TopK。

RAG · Advisor · Metadata Filter
⇄

Vue + EventSource 流式交互

前端通过 EventSource 消费 SSE，持续展示模型内容；后端同时实践 Flux、ServerSentEvent 与 SseEmitter 等流式输出方式。

Vue · Vite · SSE
∞

多轮会话记忆

MessageChatMemoryAdvisor 自动装配历史消息，conversationId 隔离不同用户会话，并通过窗口大小控制 Token 成本。

⌘

Tool Calling + MCP

地图、网页、文件和 PDF 等本地工具与 MCP 工具统一暴露给模型，降低智能体对具体实现的依赖。

◇

ReAct 执行边界

状态机、最大执行步数和显式终止工具限制循环，工具响应完整写回上下文以驱动下一轮决策。
