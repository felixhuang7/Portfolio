THREE AGENTS

同一套 AI 基础设施，服务三种任务形态

不是把三个聊天框放在一起，而是按场景差异选择记忆、Prompt、工具与执行控制策略。

DOMAIN AGENT

TripMind：从偏好到可执行旅行计划

将目的地、日期、兴趣和预算注入结构化 Prompt；通过高德地图工具与 MCP 获取地点、路线等外部信息，再输出按天编排、带花费明细的攻略，并支持生成 HTML / PDF。

  • 工具结果补足模型不具备的实时地理信息
  • 结构化输入降低遗漏，预算约束贯穿每日行程
  • SSE 逐段输出，缩短长攻略的首屏等待时间
GENERAL-PURPOSE AGENT

MyManus：自主选择工具的通用智能体

基于 BaseAgent → ReActAgent → ToolCallAgent 三层抽象实现状态、思考与行动。模型选择工具，后端执行并把观察结果写回上下文，循环至主动终止或达到 5 步上限。

  • 手动关闭框架内置工具执行，完整掌控调用历史
  • 文件、网页、资源下载、终端、PDF、高德地图与终止工具统一注册
  • IDLE / RUNNING / FINISHED / ERROR 状态防止非法重复执行
CONVERSATIONAL AGENT

情感大师：有边界的多轮陪伴

通过外置 Prompt 模板约束共情节奏、安全红线与表达方式；MessageWindowChatMemory 以 chatId 隔离会话并保留最近 20 条消息，让回复保持上下文连续。

  • 同步、Flux SSE、ServerSentEvent、SseEmitter 多种接口实践
  • ChatClient + MessageChatMemoryAdvisor 组合对话记忆
  • 提示词明确危机识别、非诊断边界与本地求助引导
REACT LOOP

一次复杂任务如何从自然语言走到工具执行？

核心不是一次模型请求，而是“思考—行动—观察”的受控循环。

1

接收任务

校验状态与输入，将 UserMessage 加入智能体上下文。

2

模型思考

带系统 Prompt 和可用工具清单请求模型，解析 ToolCall。

3

执行工具

ToolCallingManager 调用 Java 工具或 MCP Server。

4

写回观察

将助手调用与 ToolResponse 一并追加到会话历史。

5

继续或终止

无工具、主动 terminate 或达到步数上限时结束。

IDLE→RUNNING→FINISHED异常分支 → ERROR
ENGINEERING HIGHLIGHTS

把 AI 能力做成可维护的 Java 应用

页面内容均来自当前项目源码与简历知识点，数据口径采用可由代码直接验证的事实。

∞

多轮记忆与会话隔离

MessageChatMemoryAdvisor 在调用链中自动装配历史消息；使用 conversationId 区分用户会话，并通过固定窗口控制上下文长度与 Token 成本。

ChatMemory · Advisor
⇄

三种 SSE 实现对比

分别实践 Flux<String>、Flux<ServerSentEvent> 与 SseEmitter，既理解 WebFlux 数据流，也处理传统 MVC 中的异步推送、超时和完成回调。

Reactor · SseEmitter
⌘

MCP + 本地工具

通过 ToolCallback[] 统一暴露 MCP 与 Java 工具，让智能体只面向能力描述选择工具，降低业务层对具体集成方式的感知。

◎

可插拔 Advisor

日志 Advisor 同时覆盖同步与流式调用；Re-Reading Advisor 在请求前改写 Prompt，展示调用链前后增强能力。

◇

安全执行边界

最大步数避免无限循环，显式终止工具结束任务，状态机约束生命周期；工具结果完整回填，使下一步决策有据可依。
